## v3 — Complete & Stable

v3 is production-ready. The core library is feature-complete with 98.4% coverage, 18 code-generator
detectors, a deterministic documentation-generation pipeline, comprehensive CI/CD, and a full
documentation website.

### What's Done

- **18 code generator detectors** — sqlc, templ, go-enum, protobuf, oapi-codegen, deepcopy-gen,
  wire, moq, mockgen, stringer, mockery, ent, gqlgen, easyjson, msgp, counterfeiter, go-swagger,
  plus a generic `// Code generated by` fallback
- **Three-phase detection** (filename → config-aware SQLC → content) with trace support
- **Functional options API** with include/exclude glob patterns, custom `fs.FS`, pre-read content
  variants, and structured `FilterResult` with traces
- **Content-return API** — `FilterDetailedAndContent` returns file content from the lazy phase-2
  read, eliminating double-reads for callers that need the content
- **Scan API** — `ScanProject` walks `fs.FS`, returns per-generator lists + exclusion regex patterns
- **SQLC config discovery** — v1 and v2 formats, output directory extraction, config-aware detection
- **Branded error system** with sentinel errors, `ErrorCode` type, `FileReadError`, `errors.AsType` migration
- **Deterministic documentation pipeline** (`cmd/gendocs`) — Derives `generators.json`, README
  tables, `generators.mdx` (table + count), `detection.mdx` (function table), and `doc.go` from the
  single `detectors` table; CI enforces freshness. Dynamic column-width formatting via
  `formatMarkdownTable`; `markdownRow` helper structurally prevents `||` phantom-column bug.
- **Comprehensive testing** — table-driven, fuzz, property, benchmark, BDD (~174 Ginkgo specs),
  concurrent, README table-consistency regression test, gendocs integration + idempotency tests
- **Website** — Astro + Starlight with landing page (3-color accent system, funnel logo, dracula
  syntax theme, before/after proof), docs, dependents page, Firebase Hosting
- **Reproducible dev environment** — `flake.nix` (flake-parts + treefmt-nix)
- **CI/CD** — Go CI (test/race/coverage/lint/govulncheck/code-duplication/docs-freshness),
  Benchmark tracking, Website build+deploy, Release, Lighthouse (advisory), GitHub Actions pinned
  to SHA hashes

## v4 — golangci-lint Plugin

**Decision: v4 is greenlit. The golangci-lint plugin is the north star.**

### Why a golangci-lint Plugin?

golangci-lint is the most widely used Go linter (>50k GitHub stars, de facto standard). Its built-in
generated file detection is limited:

| Feature                                  | golangci-lint built-in | gogenfilter                          |
| ---------------------------------------- | ---------------------- | ------------------------------------ |
| `// Code generated` comment              | lax + strict mode      | yes (header-only, Go-spec compliant) |
| Filename patterns (*.sql.go, *_templ.go) | no                     | yes (18 generators)                  |
| Config-aware (sqlc.yaml output dirs)     | no                     | yes                                  |
| Custom detector registration             | no                     | planned (v4)                         |
| Exclusion pattern derivation             | no                     | yes (ScanProject → regex patterns)   |

gogenfilter fills a real gap: it detects files golangci-lint misses.

### Plugin Architecture (Module Plugin System)

golangci-lint v2 supports **module plugins** — compile-time embedding via `.custom-gcl.yml`.
This avoids the platform-restricted Go `plugin` package.

The plugin will:

1. Implement the `register.LinterPlugin` interface (`BuildAnalyzers()`, `GetLoadMode()`)
2. Use `go/analysis` to inspect `pass.Files` — bridging gogenfilter's file-level detection to the
   `go/analysis` package-level model
3. Provide configurable behavior: warn on generated files, auto-exclude, or report diagnostics

### v4 Scope

1. **golangci-lint plugin** (module plugin) — the headline feature
2. **Custom detector registration API** — `RegisterDetector(...)` for proprietary generators
3. **Breaking changes cleanup** — remove deprecated patterns, simplify API surface for the new
   `/v4` import path

### v4 Module Structure (proposed)

```
github.com/LarsArtmann/gogenfilter/v4
├── /          — core library (detection, filter, scan)
├── /plugin    — golangci-lint module plugin
└── /cmd/gendocs — documentation generator
```

## Evaluated and Deprioritized

- **Branch protection / required status checks** — Rejected. This is a solo-maintainer repo with a
  linear `master` workflow and no PR-based collaboration.
- **Pre-commit hook integration** — Poor fit. Generated files are routinely committed.
- **WASM build** — No clear use case.

## Backlog (unprioritized)

- **Migrate to Go 1.27** — Makes `encoding/json/v2` native, dropping the `GOEXPERIMENT=jsonv2`
  requirement. Cost: bumps the `go.mod` minimum.
- **Community feedback** — GitHub Discussions or Discord for real-world usage data
- **Supply chain hardening** — Sigstore signing, SLSA provenance, SBOM generation
