My `git commit --amend` changed the message but did NOT fix the author (I didn't pass `--author`). The `Unknown Author` identity comes from the BuildFlow hook using a git config that isn't set to Lars's identity.

**Impact:** If pushed, the git log will permanently show "Unknown Author" for the release commit. This looks unprofessional in the release history.

### 2. BuildFlow Hooks Hijacked the Release Process

**Severity: HIGH** — Loss of control over commit sequence.

A BuildFlow pre-commit hook auto-committed my staged changes before I could commit them manually. Then a post-commit hook committed dependency updates on top. This means:

- I never had control over when the commit happened
- The commit message was initially wrong (generic auto-generated)
- A second unexpected commit was created
- The tag no longer points to HEAD

**Root cause:** BuildFlow hooks are configured to auto-commit on every file change, racing with manual git operations.

**Severity: MEDIUM** — `v3.3.1` tag → `62a8ac8`, but HEAD → `5885049`. If pushed as-is, the dependency bump commit sits in master but isn't part of the tagged release.

## e) WHAT WE SHOULD IMPROVE

### Release Process Improvements

1. **No release runbook** — There's no documented release checklist. Each release is ad-hoc. A `docs/release-checklist.md` or RELEASING.md would prevent skipping steps.
2. **No version constant in source** — Go libraries typically don't need one, but having no single source of truth for "what version are we on" (beyond git tags) makes tooling harder.
3. **CHANGELOG `[Unreleased]` was already populated** — The unreleased section had content from the previous session. This is good practice, but means I didn't need to do research — I should have just promoted it.
4. **BuildFlow hooks fight manual git operations** — The auto-commit hooks make controlled releases nearly impossible. Consider disabling BuildFlow auto-commit for release workflows, or running releases in a mode that bypasses hooks (`--no-verify`).

### Documentation Drift

5. **FEATURES.md is 6 weeks stale** — Dated 2026-06-11. Should be updated as part of every release.
6. **TODO_LIST.md is 6 weeks stale** — Still shows v3.2.0 as latest. Should be updated as part of every release.
7. **No release documentation step in CI** — CI checks docs freshness (gendocs) but not FEATURES.md/TODO_LIST.md staleness.

### Pre-Existing Issues Noticed (NOT caused by this session)

8. **BuildFlow go-structure-linter: 41 findings** — All pre-existing. Root-package-files (library is intentionally at root), github-actions-pinned (actions use tags not SHAs). These are design decisions, not bugs.
9. **BuildFlow gomod-check: "direct and indirect requires are mixed"** — go.mod actually has separate `require` blocks. Likely a false positive or the hook's own go.mod modification.
10. **BuildFlow nix-checker: vendorHash warnings** — Pre-existing. Inline vendorHash values in flake.nix.
